## Төслийн тухай

Энэхүү лабораториор Session-Based Test Management (SBTM)
аргыг ашиглан «Уншлагын жагсаалт» вэб аппын чанарыг шалгана.

## Файлын бүтэц

- `charter.md` — тестийн төлөвлөгөө
- `session-report.md` — exploratory session-ийн тэмдэглэл
- `bugs/` — согогийн тайлангууд
- `evidence/` — API тестийн нотолгоо
- `screenshots/` — согогийн дэлгэцийн зураг

## Дүгнэлт

Энэхүү лабораторийн ажлаар SBTM аргыг ашиглан уншлагын жагсаалтын аппад гурван аяллаар exploratory testing хийж, нийт долоон согог илрүүлэв. Хамгийн үр дүнтэй нь Supermodel аялал байсан бөгөөд энэ аяллаар нийт номын тоолуурын зөрүү (BUG-01), хайлтын том жижиг үсэг ялгадаг алдаа (BUG-04), давхардсан ном нэмэх боломж (BUG-06), устгах товчны өнгөний зөрүү (BUG-07) илэрсэн. Couch Potato аяллаар хоосон талбартай ном нэмэх боломж (BUG-02) болон 1000-аас бага, 2100-аас их онтой номыг зөвшөөрөх асуудал (BUG-03) илрэв. Saboteur аяллаар буруу JSON хүсэлтэд `400 Bad Request`-ийн оронд `200 OK` буцааж байгааг (BUG-05) илрүүлсэн. Charter-аас гадуур урт гарчигтай номын харагдах байдлыг нэмэлтээр шалгахад хүснэгтийн бүтэц эвдэрсэнгүй. Гэхдээ зөвхөн зай агуулсан оролт, маш урт зохиолчийн нэр, тусгай тэмдэгт болон API-ийн бусад буруу хүсэлтүүдийг бүрэн шалгаагүй тул дараагийн session-д эдгээрийг туршихаар төлөвлөнө. Playwright автомат тестээр хоосон талбар, он жилийн хязгаар, давхардал, хайлтын үр дүн, номын тоолуур болон API-ийн HTTP статусын алдааг шалгаж болох байсан. Харин устгах товчны өнгө, мессежийн ойлгомжтой байдал, урт гарчигтай үеийн харагдах байдлыг хүний нүдээр шалгах нь илүү тохиромжтой. Энэхүү туршилт нь төлөвлөсөн аяллуудыг системтэй хэрэгжүүлэх, согогийг давтан гаргах алхам болон нотолгоог баримтжуулахын ач холбогдлыг харууллаа.
